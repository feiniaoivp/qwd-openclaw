# 2026-10-01（周四，国庆休市）

## 🔴 发现并修复 is_trading_day() 节假日拦截失效 bug
- **症状**：用户会话中调用 `is_trading_day()` 对 2026-10-01（国庆）返回 True。
- **根因（实测确证）**：`ak.tool_trade_date_hist_sina()` 的 `trade_date` 列是 **datetime.date 对象**（非字符串），`close_scan_v2.py` 旧代码用字符串 `today_str` 去匹配 → 永远 False → 走到函数末尾 `return True` 默认放行。**节假日拦截完全失效**（仅剩周末 weekday 检查在工作），今早 06:00 流水线因此照跑"10-01"报告。
- **修复**：`cal_dates = set(trade_cal["trade_date"].astype(str))` 统一转字符串后匹配；在日历中 = 开市 True，不在 = 休市 False。修复后验证：今天返回 False ✅
- **验证数据源**：sina 交易日历显示 09-30 之后直接跳 10-08（国庆休市 10-01~10-07）；新浪实时行情 sh000001 报价日期停在 2026-09-30 16:19。
- **教训**：与 08-02「新浪日K接口」不同，这是新坑：**pandas 列元素类型必须实测 repr() 确认，不能假设与字面量同类型**。日期列尤其常见 date vs str 错配。
