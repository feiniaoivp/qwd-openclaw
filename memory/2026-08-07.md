* **环境**: 建了独立 venv `.venv-ml`（Python 3.11.15）。原因：Intel Mac + Python 3.13 下 torch 无法安装（torch 2.2.2 是最后一个 macOS x86_64 版本，仅支持 py≤3.11）。**版本锁定**: torch 2.2.2 / faiss-cpu 1.15.0 / sentence-transformers 3.4.1 / transformers 4.49.0 / numpy 1.26.4（numpy 必须<2，否则 torch 2.2.2 崩溃）。

### 2026-08-07 daily-a-share-telegram-push 超时排查修复 ⭐
* **现象**: 收盘推送 cron 超时，lastRunStatus=error "job execution timed out (tool-execution-started)"，duration 120321ms(正好120s timeout)，且 [ALERT] 错误≥3。
* **根因(多层)**:
  1. **数据源慢+重试**：`analysis/service.py get_daily_hist` 先试 pytdx→akshare(东财,本地被拦 RemoteDisconnected)→新浪，akshare 每次失败 sleep(3) 重试3次 → 30只股纯空转 ~270s。**修复**: 新浪日K提到第一(实测0.1s/只),akshare只试1次不sleep。
  2. **trader_stock_picks 低效+崩溃**：`_akshare_call` 3次重试×sleep(2) 拉东财财务/资金流(被拦)，29只→拖30s+；且 `score_fundamentals` 里 key 误写 `"roe, 0"`→roe=None→`roe>15` 崩溃(NoneType)。**修复**: _akshare_call改单次失败即None；修 key 笔误；score_* 加 `or 0` 兜底。
  3. **LangGraph 整图重试失控**: `should_continue` 在 error_count<3 时整图回环(fetch_spot 起),每轮重跑30只全扫描+操盘手选股~30s,实测跑8+轮直到被 kill。**修复**: 改为单遍线性执行(should_continue 直接 END)。
  4. **node_check_done 逻辑反了**: 原文 `risk_flag != "致命风险"` 使致命风险时 done 恒 False→空转。**修复**: 仅需 signals齐+report_text即 done。
  5. **LLM 未配置**: `analysis/llm_tool` 默认调 api.openai.com 且 OPENAI_API_KEY 未设置→401。health_comment/risk 都是错。**修复**: 加 rule_health_comment / rule_risk_advice 规则化兜底，不依赖 LLM。
  6. **report_text 不落盘**: node_make_report 在 graph 条件边字段传播丢失。**修复**: run_agent.py 增加 build_report_text 从 final_state 直接拼报告，不依赖 graph 内字段。
  7. **risk 误判**: rule_risk_advice 早期用了 score<35/>65(误以为0-100分)，实际 calc_full_signal 的 score 是 -3~+4 小整数(level已语义化)，导致 all SELL+致命风险。**修复**: 纯按 level 子串(强烈卖出→SELL/关注·强烈买入→BUY/其余HOLD)，致命风险需≥10个强烈卖出或数据大面积失败。
  8. **新浪实时偶发断流**: node_fetch_spot 加 3 次重试(间隔1s)。
* **结果**: 超时修复后稳定运行 48-82s(<120s),exit=0,无ALERT,报告完整(市场概览/信号分布/风险/逐股建议)。cron timeoutSeconds 120→240 余量。
* **⚠️ 教训**: `analysis/agent/` 与 `analysis/service.py` 等文件含大量 `\uFFFD` 损坏字符(早期编码事故写入)，导致字符串匹配/编辑易踩坑，需 `re.sub(r'[\ufffd\ufeff\s]','',x)` 归一化或用正则按字节处理。
