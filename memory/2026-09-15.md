
## 20:15 — 斐波时间线审查：随机基准对照证伪原判定 ⭐

**触发**: 用户让审查 `close_scan_v2.py` 斐波时间线接入（commit 58f5ad1）"干得咋样"。

**审查发现（3 个问题）**:
1. **原「62.84% ≥ 40% → ✅通过」判定无效** —— `detect_reversal` 的「结构破坏(突破前20日压力±2%)」
   与「趋势加速(放量新高/低)」判据在 20+ 交易日窗口上本身就是大概率事件，**判定器自然命中率约 63%**，
   任何窗口扔进去都过 40%。
2. **设计文档 §5.3 要求的「随机基准对照」在脚本里是 `pass` 占位**
   （原文注释: "随机基准需更完整的市场级回测，暂略"），从未真正跑过。
3. **验证与生产漂移** —— 脚本内自带 `compute_fib_time_targets_local`「本地复刻」，
   而 P1.5 刚消除重复实现；回测验的 ≠ 生产跑的。

**独立对照实验（我跑的）**: 复用同一 `detect_reversal`，把 Fib 窗口换成随机窗口
（同股票/同基准日/同长度/随机偏移1~40交易日），404天×35只：
| 组 | 窗口 | 命中 | 命中率 |
|---|---|---|---|
| Fib | 14,092 | 8,877 | **62.99%** |
| 随机 | 13,258 | 8,398 | **63.34%** |
| 超额 | | | **−0.35pct** (95%CI[-1.49,+0.79] 含0) |

按窗口宽度分层：0-2d +1.3 / 3-5d −1.7 / 6d+ −1.2 —— 宽窗口高命中率纯属算术效应，各层均不显著。

**修改（用户批准的第1、4条）**:
1. `fib_time_backtest.py`: ①新增真实随机基准对照 ②判定改为「超额(95%CI下界>0)且≥15pct」
   ③报告新增随机基准/超额/CI/显著性/宽度分层表 ④删除本地复刻(-119行)改转发生产实现
   ⑤明细 JSON 默认裁剪 200 条样例(13MB→223KB，`--full` 导全量)
2. `fib_track.py build_take_profit_section`: 时间线小节加「已判定无效/仅观察性展示」警示
3. 新增 `analysis/fib_time_random_benchmark_2026-09-15.md` 记录检验过程
4. Git: `8b88d2c`

**结论**: 斐波时间线**判「弃用」** —— 不提供超出随机选日的预测信息量，不得进入决策链。

**遗留（未执行，待决策）**: ①`close_scan_v2` 的 `fib_time_windows` 仍按 (strength, window_start) 排序，
会把起点=today+1、宽度达15自然日的窗口排最前(今日27只里17只起点09-16) —— 展示的恰是最宽最无效的窗口；
②`next_window` 语义缺陷：`idx_to_date` 跳周末硬外推致 fib=1 永远=明天，且不避节假日(10-01被当交易日)；
③`hits` 未去重：同一锚点多个邻近 fib 被算作独立来源，系统性高估 strength；
④提交说明称 `signal` 内新增 `fib_time`，实际在 `watchlist_scan` 条目**顶层**（文档与实现不一致）。

**教训（写入 MEMORY 级）**: 回测判定必须在**判定器自身的自然命中率**之上做**随机基准对照**，
单一绝对阈值（如 40%）在「宽窗口+宽松判定器」组合下必然失效 —— 这正是射箭画靶的另一种形态。
