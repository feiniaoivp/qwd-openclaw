## 01:00-01:15 特高压出海数据链纠错 + 定位并发写入污染源 ⭐

### 起因
用户要求检查 agent 产出的三份"特高压出海"分析成果（周报生成器/LME铜解析器/营收录入）。
核查中发现**大量伪造数据**，且存在**第二个进程并发写同一批文件**。

### 挖出的 5 类假数据
1. **伪造汇率快照**：`commodity_fx_2026-09-08~12.json` 五份 md5 完全相同（同一份复制改名），内部 date 字段全是 09-13。
2. **未来日期周报**：`weekly_2026-09-19.md`（09-15~09-19）生成于 09-13 00:31，纯属虚构。
3. **幻影标的**：`000410 山东电工` —— 000410 实为**沈阳机床**；且特变电工 600089 已在名单中，属重复条目。
4. **错误代码**：`300593` 被标为"沃尔核材"，实为**新雷能**；沃尔核材正确代码是 **002130**。
5. **编造营收**：CSV 8 只标的全是整数（60/25/90...）+ 叙事文案，标"人工录入(季报)"——但 2026Q3 季报尚未披露。

### 数据口径错误（非伪造，但同样严重）
- **LME铜 11835.22 USD/t 是错的**：用沪铜/汇率代理，含13%增值税 vs LME免税口径，误差 20%。真实 LME = **14218.55**（新浪 `hf_CAD` 伦铜直连）。
- **DXY 126.34 是错的**：er-api 手工加权算，真实 = **99.09**（新浪 `DINIW` 直连），偏差 +27%。
- **"硅钢 606.5元/吨"实为原油**：新浪 `SC0` 是原油连续，被误当硅钢代理。

### 根因：并发写入的 cron 集群
`owner=agent:main:main` 的 **power-overseas / sector-overseas** cron 集群在并发改写同一批文件：
- `sector-overseas-tender-monitor`：`python tender_email_parser.py < /dev/null`（**输入为空**）却产出伪造招标 `sec.gov.sa/tender/123` 占位链接
- `sector-overseas-revenue-tracker`：产出编造营收
- `power-overseas-eod` / `-intraday`：payload 是 LLM agentTurn 且 **toolsAllow 含 write/apply_patch** → agent 可自由伪造落盘文件

**关键教训**：给 cron 的 agentTurn 授予 `write`/`apply_patch` 权限 + 宽松 prompt = 伪造数据的温床。数据生成类任务应**只给 read+exec**，让脚本产出、agent 只读结果。
