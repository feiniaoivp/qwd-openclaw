### 🔴 过程中挖出的真 bug（比需求本身更重要）
**现象**：同一份代码，`python3 -c "import ...; check_historical_judgment_review(...)"` 返回
`hist_date=2026-09-11, T+5=-1.84%`；但 `python3 analysis/challenge_review.py` 返回
`hist_date=2026-09-18, T+5=None`。反复清缓存、清 pycache、改去重逻辑都无效。

**定位过程**（关键：不要靠猜，注入诊断打印真实异常栈）：
1. 在 `_get_close_series` 的 except 分支打印 `repr(e)` + traceback
2. 立刻暴露真因：
   ```
   ModuleNotFoundError("No module named 'analysis'")
   File ".../analysis/data_layer/__init__.py", line 20, in <module>
       from analysis.data_layer.router import DataRouter, get_router
   ```

**根因**：脚本模式运行时 `sys.path[0]` 是 `analysis/` 而非**工作区根**，
因此 `data_layer/__init__.py` 里写死的 `from analysis.xxx import` **导入失败**；
而该异常被 `except Exception` **静默吞掉** → 价格序列全空 → T+5 全 None
→ 报告误报"数据不足/待观察"。

**为什么极难发现**：
- `python3 -c` 方式下工作区根**已在 sys.path**（cwd），所以两种运行方式行为不同
- 异常被 catch 后只走 `log.debug`，默认不可见
- 表面看像"网络抖动"，会误判为环境问题而放弃排查

**修复**：模块顶部（第 17 行 WORKSPACE 定义后）同时插入 **工作区根 + analysis/**，幂等。
```python
for _p in (WORKSPACE, os.path.join(WORKSPACE, "analysis")):
    if _p not in sys.path:
        sys.path.insert(0, _p)
```

⚠️ **这是本项目第二次踩同类坑**（记忆 2026-08-23 已记："顶层包/相对导入靠 sys.path 时，
脚本须同时插工作室根 + 子目录；PYTHONPATH 只在交互 shell 生效，定时/子进程不继承"）。
→ 说明该教训**未固化为代码模板**，仅停留在记忆里。建议后续新建脚本一律带这两行 sys.path 样板。
